발끝 depth 검증 도입 - 근본원인 규명과 실측 (2026-08-09, my_new_bag5)

■ 근본원인: ID 문제가 아니라 '측정' 문제였다

외형 임베딩/Hungarian/갤러리를 다 넣어도 점프가 하나도 안 줄어 원인을 다시 팠다.

1) 라이다는 무관하다
   지금까지의 A/B는 oakd_detector_node + reid_tracking_node만 띄웠고
   leg_detector_bridge_node는 한 번도 실행되지 않았다. 관측된 점프는 전부 OAK-D 경로.

2) ID 로직 이전의 '원시 측정값'이 이미 튄다 (tools/measure_detection_jitter.py)
   같은 YOLO track_id의 연속 프레임 사이 3D 좌표 변화:
     중앙값 0.194m / 90% 0.658m / 최대 1.486m(7.48m/s) / 0.5m 초과 12회
   같은 실행의 target_person_pose 0.5m 초과 점프도 정확히 12회.
   => 추적기가 측정 노이즈를 그대로 통과시키고 있을 뿐, 엉뚱한 사람에게 붙는 게 아니다.
      (Track.update의 position_alpha가 평소 1.0이라 위치를 측정값에 그대로 스냅한다)

3) 튀는 성분은 거리(depth)다
   변화를 분해하면 depth 방향 0.4m 초과 15프레임 vs 가로(픽셀) 5프레임.
   큰 점프에서 depth가 2.51->1.04, 2.15->1.16처럼 배경 거리 2.51m가 반복 등장했고,
   프레임별 depth 중앙값(대체로 배경)이 1.43~2.51m 범위였다.
   => 발끝 픽셀 주변이 사람 신발이 아니라 뒤쪽 벽/바닥을 찍는 순간 거리가 배경값으로 튄다.
      스테레오가 저텍스처 바닥/실루엣 경계에서 약한 전형적 실패.
   덧붙여, 큰 점프가 전부 최고 신뢰 등급(toe_direct)에서 났다 - 즉 기존 grade/covariance는
   실제 오차를 반영하지 못하고 있었다.

■ 조치: vision_utils.estimate_person_depth
   bbox 안쪽(좌우 20% 잘라냄)의 낮은 분위수(20%)로 '사람 표면 깊이'를 구하고, 발끝 depth가
   이와 0.4m 넘게 어긋나면 사람 깊이로 대체한다(사람은 자기 bbox 안에서 배경보다 항상 가깝다).
   대체 시 grade를 toe_direct -> knee_corrected로 낮춰 covariance에 불확실도가 반영되게 했다.
   근거 방식: RGB-D 사람추적에서 단일 픽셀이 아니라 사람 영역 통계를 쓰는 표준 접근
   (Munaro & Menegatti, Fast RGB-D people tracking for service robots, Auton. Robots 2014).
   파라미터: depth_consistency_tolerance(기본 0.4, 0이면 끔), depth_person_percentile(20).
   진단 키 depth_substituted를 /diagnostics에 추가 - 이 값이 크면 IPM 도입을 검토할 근거.

■ 실측 (my_new_bag5, 격리 도메인, 재생 rate 1.0 고정)

  원시 측정 단계 (tools/measure_detection_jitter.py)

[정정 - 2026-08-09] FOLLOWING 오버레이가 착시를 주고 있었음 (사용자 지적)

사용자가 "사람이 화면에 나오기만 하면 저항 없이 마젠타가 된다"고 지적해 확인한 결과,
오버레이에 **거리 상한이 없었다**. 가장 가까운 검출을 무조건 FOLLOWING으로 칠했기 때문에
화면에 사람이 하나면 추종 대상과 몇 미터 떨어져 있든 항상 칠해졌다.

  수정: follow_target_match_distance(기본 0.8m) 초과면 표시하지 않고 'TARGET NOT VISIBLE'.
  효과(my_new_bag5 동일 조건): FOLLOWING 표시 88프레임 -> 55프레임, NOT VISIBLE 0 -> 96프레임.
  => 이전 영상은 프레임의 약 1/3에서 "추종 대상이 아닌 사람"을 추종 중인 것처럼 보여줬다.

[중요] 그래서 ID 유지는 실제로 잘 되고 있나? -> 아니다. 시각화만의 문제가 아니었다.
target_person_pose가 어느 트랙에 붙어 있는지 시계열로 추적한 결과, 추종 대상이 실제로
다른 사람으로 건너뛴다:
  depthfix       : 전환 4회 (다른 사람으로 점프 3회: 1.11m / 0.71m / 1.02m, 번호만 바뀜 1회)
  depthfix+라이다 : 전환 2회 (다른 사람으로 점프 1회: 1.32m, 번호만 바뀜 1회)

따라서 이번 depth 수정이 개선한 것은 **좌표 정확도(측정 노이즈)**이지 **신원 유지**가 아니다.
두 축을 분리해서 봐야 한다:
  - 좌표 정확도: 최대 점프 3.05m -> 1.22m  (개선됨, depth 수정 효과)
  - 신원 유지  : 추종 대상이 여전히 다른 사람으로 건너뜀 (미해결)
신원 유지가 안 되는 원인은 추종 대상 선정이 아직 "가장 오래된 트랙"이라는 임시 정책이기
때문이다(_maybe_select_followed_track). 추종 트랙이 track_timeout(3초)으로 사라지면 그 시점에
살아있는 다른 사람을 그냥 고른다. 웹캠 호출 좌표 기반 대상 지정 + sticky follow가 들어가야
해결된다.

파일: evidence_follow_overlay_gated_bag5.mp4 (거리 상한 적용 + 라이다 포함 실행)
